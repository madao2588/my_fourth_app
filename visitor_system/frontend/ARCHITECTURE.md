# 前端骨架说明

当前前端采用“双线结构”：

- 微信小程序：面向访客
- Web：面向管理员，同时保留访客备用入口

本轮骨架搭建的目标不是替换现有可运行原型，而是补齐后续演进所需的目录层级，让页面、模块和组件有明确落点。

## Web 规划

建议按职责拆分为：

- `src/pages/visitor/`
  - 访客首页
  - 预约表单
  - 查询结果
  - 电子凭证
- `src/pages/admin/`
  - 仪表盘
  - 待审批
  - 现场操作
  - 历史记录
  - 系统日志
  - 账号管理
- `src/components/`
  - 通用卡片
  - 状态标签
  - 空状态
  - 表单块
- `src/store/`
  - 管理员登录态
  - 页面筛选状态
- `src/utils/`
  - 时间格式化
  - 状态映射
  - 前端校验

## 微信小程序规划

建议按访客流转组织：

- `pages/home/`
  - 首页入口
- `pages/apply/`
  - 预约表单
- `pages/result/`
  - 提交结果
- `pages/query/`
  - 预约查询
- `pages/pass/`
  - 电子凭证
- `components/`
  - 状态卡片
  - 字段展示块
  - 凭证卡片

## 说明

- 当前仓库已有可运行原型，本次新增骨架文件以“补位”为主
- 新增模块文件默认是占位骨架，后续可逐步迁入现有逻辑
- 这样做可以避免前端继续长功能时全部堆进单个脚本
